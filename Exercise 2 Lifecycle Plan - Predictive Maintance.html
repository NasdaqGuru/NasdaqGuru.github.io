● Use Case 2 · Facilities & Operations

Predictive Maintenance Lifecycle Plan

For every monitored asset — chillers, boilers, elevators, pumps, generators, air handlers — the model predicts failure risk and the system decides continue normal operation, schedule maintenance within X days, inspect immediately, or take offline. Lifecycle

Six stages · one deliverable each

Select a stage to see its deliverable, activities, exit criteria, and owners.

Stage 01

Problem definition

📄 Decision Charter & Asset Criticality Matrix

What happens

  • Define the decision: continue, schedule maintenance, inspect now, or take offline.
  • Build the asset criticality matrix — rank assets by failure impact, cost, and safety.
  • Identify target failure modes per asset class (bearing, belt, refrigerant, winding, valve, sensor).
  • Establish baseline: current unplanned downtime hours, cost per failure, MTTR.
  • Set guardrails: false positive ceiling, safety floor, availability floor.
  • Quantify ROI: avoided downtime × cost per hour vs. program cost.
Owner: Facilities & OperationsApprover: VP Operations

Exit criteria

Decision documentedCriticality matrix signedBaseline measuredROI approvedOwner named

Stage 02

Data readiness

📡 Sensor & Data Readiness Pack

What happens

  • Inventory sensors: vibration, temperature, pressure, current, flow, run-hours.
  • Map asset registry: make, model, install date, duty cycle, service history.
  • Extract maintenance logs: work orders, parts replaced, failure codes, technician notes.
  • Integrate weather and occupancy data — ambient conditions drive asset load.
  • Label failure events: type, severity, lead time, root cause where known.
  • Establish governance: sensor data ownership, retention, calibration schedule.
Owner: Facilities Data & DigitalPartner: IT · OT · Vendors

Stage 03

Model development

🧠 Model Card & Benchmark Report

What happens

  • Baselines: calendar-based maintenance, threshold alarms, statistical process control.
  • Candidates: anomaly detection (Isolation Forest, autoencoder), survival analysis (Weibull), classification (XGBoost, LSTM), remaining useful life (RUL) regression.
  • Benchmark: prediction accuracy, lead time (days of warning), false positive rate, false negative rate.
  • Evaluate per asset class and per failure mode — one model rarely fits all.
  • Publish model card: training data window, asset coverage, known failure modes, limits.
Owner: ML EngineeringPartner: Facilities Engineering · Vendors

Exit criteria

Stage 04

Validation

✅ Validation Report & Failure Mode Coverage Matrix

What happens

  • Seasonal holdout: test on summer peak, winter heating, shoulder, and humidity seasons.
  • Machine holdout: test on assets not seen in training — new, old, different OEMs.
  • Failure-type holdout: test on each failure mode; document coverage gaps.
  • Operating-mode stress: startup, steady-state, peak load, idle, transient.
  • Cost-of-error analysis: weight false negatives (missed failure) vs false positives (over-scheduling).
  • Shadow mode: run predictions alongside current maintenance for 90 days.

PdM Validation

Validation scenarios

A predictive maintenance model must hold up across seasons, machines, failure types, and operating modes. Each dimension is a holdout — the model is tested on scenarios it has not seen in training.

Four validation dimensions

Every dimension is a separate holdout. All four must pass before deployment.

Validation scenarios by dimension, cases, and what is tested
Dimension Scenarios What we test Pass criteria
🌡 Seasons Summer peak Winter heating Shoulder Humidity / monsoon Model performance under different ambient temperature, humidity, and load profiles. Accuracy drop ≤ 5 pts vs. training-season baseline.
⚙️ Machines New (<1yr) Mid-life (1–5yr) Aged (>10yr) Different OEMs Different duty cycles Generalization across the asset population — not just the machines seen in training. Machine holdout accuracy within 8 pts of in-sample; no asset class below 70%.
🔧 Failure types Bearing wear Belt degradation Refrigerant leak Motor winding Valve stuck Sensor fault Coverage of each failure mode — does the model catch it, and with how much lead time? ≥ 80% of failure modes covered; lead time ≥ 7 days for each covered mode.
🔄 Operating modes Startup Steady-state Peak load Idle Transient Robustness across operating regimes — does the model confuse normal transients with failures? False positive rate ≤ 10% in each mode; no mode above 15%.

Cost-of-error weighting

False negative (missed failure) → unplanned downtime, safety risk, emergency repair cost. Weight: 10×. False positive (unnecessary maintenance) → over-scheduling, technician time, parts waste, trust erosion. Weight: 1×. The model is tuned to favour catching failures over avoiding false alarms — but the false positive rate is capped at 10% to protect adoption.

PdM Monitoring

Monitoring triggers

Predictive maintenance models decay differently from language models. The biggest triggers are maintenance events and part replacements — both change the asset's normal signature.

Trigger → signal → action

Every trigger has a severity, an owner, and a defined action. Severity determines whether the response is retrain, re-baseline, or rollback.

Monitoring triggers for predictive maintenance with severity, signal, action, and owner
Trigger Signal Severity Action Owner
Drift after maintenance
Asset signature shifts after service		 Post-maintenance baseline differs > 2σ from pre-maintenance Watch Re-baseline asset; re-validate model on 30 days of post-maintenance data. Reliability Eng
New part installed
Component replacement changes signature		 Vibration, current, or temperature signature diverges from fleet Watch Flag asset for 30-day observation; compare new signature to fleet baseline. Reliability Eng
Sensor drift or failure
Data quality degrades		 Flatlines, out-of-range values, or missing readings > 2% Critical Calibrate or replace sensor; exclude asset from model until data quality restored. IT/OT

New asset added
